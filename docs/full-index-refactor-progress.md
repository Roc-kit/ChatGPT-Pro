# 全文索引与导出重构：实施记录

依据：2026-10-24 冻结的 Q1–Q9 重构计划，实施顺序 S1 → S6。此文档只记录实施结果，不改变产品范围。

## 2026-10-24：S1-1 本地存储基础设施

状态：**本功能单元完成**；S1 尚未整体结束，S2–S6 未开始。

### 代码

- `scripts/local-data-store.js`：沿用已有 `ChatGPTProSearch` IndexedDB，从版本 1 原地升级到版本 2，保留原有 `conversations` 搜索区。
- 新增账号、目录、完整对话、派生搜索索引、任务、日志 6 个对象存储区。目录/对话/新索引使用复合主键 `[accountId, id]`。
- 原 v1 搜索结果复制到新搜索区的 `__legacy_unassigned__` 分区，**不**分配给当前登录账号，原有旧数据仍保留且仍可走旧搜索入口。
- 提供完整原始 JSON 的保存/读取、版本判断、账号隔离、目录写入、缓存数量统计接口。写入完整对话和匹配索引时使用同一 IndexedDB 事务；若没有新的派生索引，则移除同对话的旧派生版本，防止版本错配。
- `scripts/background.js` 接入新存储基础设施，并开放 `localDataPutConversation`、`localDataGetConversation`、`localDataUpsertDirectory`、`localDataStats`、`localDataLegacyStats` 消息接口。
- 旧 `searchIndexPrune` 暂时改成不删除：远端目录缺失不等于已确认删除；保留旧索引，直到后续有账号绑定和可信远端删除判定。

### 最小必要验收

通过：v1 → v2 升级；旧搜索结果保留且可搜索；旧数据不自动归属；账号 ID 冲突隔离；更新版本/时间戳转换与缓存过期判断；搜索派生版本失效；不完整 JSON 拒绝写入且保留旧值；新版目录与数量统计；未确认删除时不清理旧索引。

`node --check`（新版存储、后台、测试）与 `git diff --check` 通过。

4. **S4：** 首次授权、增量更新、旧数据归属处理、可靠删除确认和“仅本地”检索；目录已有 `remoteState` 字段，但不能据此声称已完成自动识别。

## 2026-10-24：S1-2 登录账号识别与正式读取路径隔离

状态：**S1 最小必要开发及隔离回归完成**；S2–S6 尚未开始。

### 代码

- `scripts/api-handler.js` 从 `/api/auth/session` 的 `user.id` 获取明确的账号 ID；不使用邮箱、昵称或旧全局缓存猜测账号。登录账号未知时拒绝读取；身份短时间复用，页面重新获得焦点时重新校验。
- 正式聊天目录改为 IndexedDB 按账号读取、增量写入；原先保存在 `chrome.storage.local` 的未归属目录原封保留，不自动迁移到某个账号。刷新只使当前账号的目录同步过期，不清空历史内容。
- 目录同步等待和存储的短期节流键以账号 ID 区分；完成同步前再次核实登录账号，账号中途变更不允许把旧结果写入新用户分区。
- `scripts/background.js` 的正式索引写入、元数据、搜索和清除动作全部要求账号 ID，只访问该账号的新版 `searchIndex`；不再清空旧版全文索引。
- 旧版 v1 索引保留在未归属分区。全文搜索界面新增**默认关闭**的“另查未归属的旧版全文索引”选项，并将结果标记为未归属（只展示旧文本片段，不推断其在线地址，也不尝试作为当前账号数据导出）。
- 账号变化或登录失效时清除页面正在展示的旧目录、时间戳和面板；Popup 周期性读取状态复用短期有效的身份缓存，不会每 3 秒请求会话。
- 没有可靠确认删除的条目继续保留；本阶段不将其猜测为“仅本地”，留给 S4 处理。

### 最小必要验收

`node tests/s1-local-data-smoke.cjs`：真实隔离 Chrome + 模拟 ChatGPT 会话/目录响应，覆盖旧版本升级、旧索引可搜索、账号切换 A→B→A、正式目录与全文索引不串账号、无 ID 拒绝读取、旧数据不被重归属、原始 JSON 不被清理、Popup 轮询不重复获取会话。

脚本静态语法检查和 `git diff --check` 通过。**没有**连接实际 ChatGPT 账号或修改已有浏览器数据库；真实账号页面的人工操作验收留到 S6，不用大量真实 API 请求替代隔离测试。

### S2 起点

下一开发单元是 **S2-1 统一 `getConversation()` 缓存访问**：调用方首先按账号 ID + 版本检查完整 JSON，详情缓存命中时不请求网络，同一次新抓取原子写入完整 JSON 与衍生搜索索引，之后逐步让 MD/JSON 导出与全文索引都走该入口。旧未归属搜索记录继续可读，但不得自动成为完整 JSON 缓存命中。

## 2026-10-24：S2-1 统一详情读取与完整 JSON 缓存命中

状态：**本功能单元完成**；S2 继续实施，S3–S6 未开始。

### 代码

- `APIHandler.getConversation()` 改为唯一入口：先识别当前账号、查当前账号的目录条目版本、读 `conversationData` 中该账号及对话 ID 对应的完整 JSON。缓存版本命中直接返回原始 JSON，**不请求详情 API**。
- 缓存缺失或版本改变时再调用原有详情 API，保存完整原始 JSON；同页相同账号/对话的并发请求共享一份进行中的 Promise。
- 使用 IndexedDB 单条目录主键查询，不为每条对话扫描全目录。旧版未归属文本索引不能自动视作 JSON 缓存命中。
- 如果读取或持久化缓存失败，保留原有在线抓取功能并记录简要警告；登录身份切换后不能将结果写到新账号的缓存。
- 新抓取若没有同版本的搜索索引，会移除过期派生索引；已有且版本相符的文本索引予以保留。针对旧数据与新数据写入竞争，拒绝把过期搜索版本写回更新后的完整 JSON 旁边。
- 单条 Markdown、单条 JSON、批量导出和现有全文索引的详情读取已经调用 `getConversation()`，因此都能命中同一份完整原始 JSON；它们的用户界面与批量调度/分卷输出逻辑还未重构。

### 测试

`node tests/s1-local-data-smoke.cjs` 使用真实隔离 Chrome 数据库、模拟会话与详情 API：100 条完整缓存的 `getConversation()` 请求 **0 次详情 API**；同一对话三路并发只发一次详情请求；另一个账号不能命中前一个账号的缓存；目录版本更新时仅重新抓取受影响对话；过期搜索记录被拒绝。

`node --check` 及补丁检查通过。此为缓存读取闭环验证；完整批量导出界面的 100 条零请求测试仍在 S2-2 / S6 执行，不重复宣称完成。

## 2026-10-24：S2-2b 批量导出分卷、manifest 与缓存命中跳过等待

状态：本功能单元完成；S2 仍需“导出前检查最新版本”可选策略，S3–S6 尚未开始。

### 实现

- 批量导出改为逐卷生成独立 ZIP：每卷最多 50 条结果，或约 24 MiB 对话正文（以先达到的限制为准）；超大单条允许独立成卷。完成一卷即发起下载，不再把全部对话正文积压在数组里。
- 每卷包含 `manifest.json`（成功、失败、对话 ID、文件名、分卷编号），最后一卷另包含全局完整清单；存在失败时，附 `导出失败.txt`，即使全失败仍输出清单卷。
- 文件名跨卷去重，保留原有 Markdown 当前分支导出格式和 JSON 包装格式。分卷命名 `ChatGPT-Pro_日期_时间_格式_part001.zip` 等。
- `APIHandler.getConversation(id, { withSource: true })` 可标记数据来自 `cache` / `network`，原有单条导出调用不受影响。缓存命中时跳过 900 毫秒请求间隔及 10 秒网络组间等待；发生网络请求时保持原有节流。
- 下载阶段只表示**已发起浏览器下载**，并不假称已保存成功。Chrome 可能提示网站是否允许连续下载多个文件；现阶段不额外增加下载权限。
- S2 尚无跨页面持久化任务检查点。已经触发下载的完整分卷不会被后续对话的转换错误吞掉，但页面关闭或浏览器阻止下载时仍需要 S3 的任务恢复和 S6 的真实浏览器验收。

### 最小测试

- `node tests/s2-bulk-export-smoke.cjs`：直接运行当前源文件中的 ZIP 编码和批量导出函数，校验 100 条缓存生成两卷、无请求节流等待、每卷 ZIP 本地条目可读取、全局 `manifest.json` 覆盖 100 个对话、跨卷重名、失败和全部失败、24 MiB 分卷、下载失败时已完成分卷仍保留。
- `node tests/s1-local-data-smoke.cjs`：真实隔离 Chrome IndexedDB 中的账号隔离与 100 条完整缓存零详情 API 回归，并覆盖 `withSource` 接口的缓存标记。
- 语法检查与 Git staged diff 检查通过。上述 ZIP 用受控模拟数据完成，实际浏览器的多次下载授权仍待集中验收。

## 2026-10-24：S2-3 可选导出前增量检查最新版本

状态：**S2 计划内核心开发单元完成**；S3–S6 尚未开始。

- 在批量导出操作区新增默认关闭的“检查更新”复选框，仅在用户明确选择后生效。
- 默认仍直接使用本地完整原始 JSON。勾选后调用现有目录增量同步，跳过短期目录节流但**不**强制完整历史重扫；将选中对话映射为最新目录记录，`getConversation()` 依照更新后的版本仅请求缺失或变化的正文。
- 检查目录失败会阻止此次要求检查的导出，不静默地将旧版本当作已确认最新。非勾选路径继续优先本地缓存。
- 注意：这是对官方“更新时间”目录的增量校验，而非逐条联网获取正文比对；若官方目录缺失、分页不完整或存在未发现的变化，并不能保证本地已绝对最新。后续 S4 处理删除状态，S3 处理统一限流与恢复。
- 验证：`node tests/s1-local-data-smoke.cjs` 中模拟目录变更，普通调用无额外目录请求、勾选后绕过目录节流、未变化的完整缓存不重新请求详情、只有变更版本的正文产生新请求。S2 分卷测试仍通过。
