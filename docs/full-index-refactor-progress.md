# 全文索引与导出重构：实施记录

依据：2026-10-24 冻结的 Q1–Q9 重构计划，实施顺序 S1 → S6。此文档只记录实施结果，不改变产品范围。

## 2026-10-24：S1-1 本地存储基础设施

状态：**本功能单元完成**；S1 尚未整体结束，S2–S6 未开始。

### 代码

- `scripts/local-data-store.js`：沿用已有 `ChatGPTProSearch` IndexedDB，从版本 1 原地升级到版本 2，保留原有 `conversations` 搜索区。
- 新增账号、目录、完整对话、派生搜索索引、任务、日志 6 个对象存储区。目录/对话/新索引使用复合主键 `[accountId, id]`。
- 原 v1 搜索结果复制到新搜索区的 `__legacy_unassigned__` 分区，**不**分配给当前登录账号，原有旧数据仍保留且仍可走旧搜索入口。
- 提供完整原始 JSON 的保存/读取、版本判断、账号隔离、目录写入、缓存数量统计接口。写入完整对话和匹配索引时使用同一 IndexedDB 事务；若没有新的派生索引，则移除同对话的旧派生版本，防止版本错配。
- `scripts/background.js` 接入新存储基础设施，并开放 `localDataPutConversation`、`localDataGetConversation`、`localDataUpsertDirectory`、`localDataStats`、`localDataLegacyStats` 消息接口。
- 旧 `searchIndexPrune` 暂时改成不删除：远端目录缺失不等于已确认删除；保留旧索引，直到后续有账号绑定和可信远端删除判定。

## 2026-10-24：S2-1 统一详情读取与完整 JSON 缓存命中

状态：**本功能单元完成**；S2 继续实施，S3–S6 未开始。

### 代码

- `APIHandler.getConversation()` 改为唯一入口：先识别当前账号、查当前账号的目录条目版本、读 `conversationData` 中该账号及对话 ID 对应的完整 JSON。缓存版本命中直接返回原始 JSON，**不请求详情 API**。
- 缓存缺失或版本改变时再调用原有详情 API，保存完整原始 JSON；同页相同账号/对话的并发请求共享一份进行中的 Promise。
- 使用 IndexedDB 单条目录主键查询，不为每条对话扫描全目录。旧版未归属文本索引不能自动视作 JSON 缓存命中。
- 如果读取或持久化缓存失败，保留原有在线抓取功能并记录简要警告；登录身份切换后不能将结果写到新账号的缓存。
- 新抓取若没有同版本的搜索索引，会移除过期派生索引；已有且版本相符的文本索引予以保留。针对旧数据与新数据写入竞争，拒绝把过期搜索版本写回更新后的完整 JSON 旁边。
- 单条 Markdown、单条 JSON、批量导出和现有全文索引的详情读取已经调用 `getConversation()`，因此都能命中同一份完整原始 JSON；它们的用户界面与批量调度/分卷输出逻辑还未重构。

### 测试

`node tests/s1-local-data-smoke.cjs` 使用真实隔离 Chrome 数据库、模拟会话与详情 API：100 条完整缓存的 `getConversation()` 请求 **0 次详情 API**；同一对话三路并发只发一次详情请求；另一个账号不能命中前一个账号的缓存；目录版本更新时仅重新抓取受影响对话；过期搜索记录被拒绝。

`node --check` 及补丁检查通过。此为缓存读取闭环验证；完整批量导出界面的 100 条零请求测试仍在 S2-2 / S6 执行，不重复宣称完成。

## 2026-10-24：S2-2b 批量导出分卷、manifest 与缓存命中跳过等待

状态：本功能单元完成；S2 仍需“导出前检查最新版本”可选策略，S3–S6 尚未开始。

### 实现

- 批量导出改为逐卷生成独立 ZIP：每卷最多 50 条结果，或约 24 MiB 对话正文（以先达到的限制为准）；超大单条允许独立成卷。完成一卷即发起下载，不再把全部对话正文积压在数组里。
- 每卷包含 `manifest.json`（成功、失败、对话 ID、文件名、分卷编号），最后一卷另包含全局完整清单；存在失败时，附 `导出失败.txt`，即使全失败仍输出清单卷。
- 文件名跨卷去重，保留原有 Markdown 当前分支导出格式和 JSON 包装格式。分卷命名 `ChatGPT-Pro_日期_时间_格式_part001.zip` 等。
- `APIHandler.getConversation(id, { withSource: true })` 可标记数据来自 `cache` / `network`，原有单条导出调用不受影响。缓存命中时跳过 900 毫秒请求间隔及 10 秒网络组间等待；发生网络请求时保持原有节流。
- 下载阶段只表示**已发起浏览器下载**，并不假称已保存成功。Chrome 可能提示网站是否允许连续下载多个文件；现阶段不额外增加下载权限。
- S2 尚无跨页面持久化任务检查点。已经触发下载的完整分卷不会被后续对话的转换错误吞掉，但页面关闭或浏览器阻止下载时仍需要 S3 的任务恢复和 S6 的真实浏览器验收。

## 2026-10-24：S2-3 可选导出前增量检查最新版本

状态：**S2 计划内核心开发单元完成**；S3–S6 尚未开始。

- 在批量导出操作区新增默认关闭的“检查更新”复选框，仅在用户明确选择后生效。

## 2026-10-24：S3-1 持久化任务及排他租约基础

状态：**S3 第一个独立功能单元完成；尚未把现有索引/导出循环切换到任务执行器。**

- 复用原有 IndexedDB `tasks` 区，不重新建库；任务按账号隔离，支持 `index` / `export-md` / `export-json`，保存对话 ID、目录版本、任务状态、下一条检查点、成功失败计数以及脱敏失败原因。
- 原子申请任务租约（30 秒有效期），以随机 token 作为 fencing 防止旧标签页在租约失效后写入；心跳续租、按序完成单条检查点、过期租约接管都在 IndexedDB `readwrite` 事务内完成。
- 暂停、继续和取消均可持久化。用户主动暂停不自动恢复；任务被接管后不能重复提交已完成记录。工作器不会以 MV3 Service Worker 的持续运行作为前提。
- `background.js` 暴露 `taskCreate`、`taskGet`、`taskList`、`taskClaim`、`taskHeartbeat`、`taskCheckpoint`、`taskControl` 消息 API；任务控制器实际执行逻辑将在后续单元接入，不能据此宣称已经实现后台持续抓取。
- 隔离 Chrome 测试覆盖双标签原子竞争、账号隔离、检查点幂等防护、暂停拦截、继续后更换租约 token、旧持有者拒写、过期接管、取消和完成计数；没有访问真实 ChatGPT 服务。

下一开发单元：将 `updateFullTextIndex` 接到持久化任务执行器并支持页面重新进入时续跑，随后统一批量导出任务状态及共享 429 冷却。

## 2026-10-24：S3-2 全文索引任务持久化执行与恢复

状态：**索引长任务已接入任务系统**；批量导出持久化、跨任务共享网络调度/429 冷却与 Popup 控件未完成。

- `content-chatgpt.js` 中全文索引按钮改为使用 `taskCreate` / `taskClaim` / `taskHeartbeat` / `taskCheckpoint` 执行；每条完成后持久化进度。页面关闭或刷新后，待任务租约超时，重新进入 ChatGPT 页面会尝试接管未完成的索引任务。
- 页面运行时每 10 秒续租、每 15 秒检查可恢复任务；执行与抢租仍在页面中，Service Worker 仅响应短消息，不依赖 MV3 worker 常驻。主动暂停或取消的任务不会自动恢复；权限/认证失败会暂停任务。
- 同一个账号同种类型的活动任务在数据库创建事务中去重：即使两个标签同时点击更新索引，也只创建一个活动任务。若任务已暂停，不隐式新建同类型任务。
- 使用原有完整 JSON 缓存与搜索派生事务写入；若缓存事务已成功但检查点前中断，恢复后最多重复执行本地转换，不要求重复调用详情 API。

- 边界：租约超时是保守恢复而非实时无缝接管；页面被关闭后不要求无人打开 ChatGPT 页面仍继续抓取。真实多标签浏览器交互和后台任务列表 UI 放到 S5/S6 验收；**导出任务暂未接入持久化执行器**。

## 2026-10-24：S3-3 同账号统一详情请求与 429 共享冷却

状态：**详情请求协调和共享冷却完成**；S3 仍有导出任务持久化、运行日志与任务管理交互待实现。

- `local-data-store.js` 在原有 `accounts` 存储区维护每账号一个详情请求租约、429 连续次数及 `cooldownUntil`，不新增数据库或外部服务。获取、心跳、释放与冷却判定采用 IndexedDB `readwrite` 原子事务。
- 详情请求同账号单并发：`APIHandler.getConversation()` 缓存未命中时进入统一调度，获得排他租约后再检查一次缓存，避免其他标签刚写入缓存却仍重复请求。网络请求与完整 JSON 保存完成后才释放租约；45 秒租约、每 10 秒续租，页面被丢弃时可超时接管。
- 429 优先按官方 `Retry-After` 冷却，没有有效值时采用递增退避（从 60 秒开始，上限 5 分钟）。冷却在不同索引/导出任务及标签之间共享，持久化到 IndexedDB；目录更新不再覆盖该状态。其他账号不受影响。
- 旧标签的租约释放不能覆盖新标签持有的租约或其冷却状态。Chrome 页面或 Service Worker 退出时租约超时可继续；无持续后台抓取保证。
- 隔离 Chrome 测试覆盖双执行者串行租约、429 冷却、其他账号独立、目录同步后仍保留冷却、冷却到期可继续、旧租约不能改状态。既有 S1/S2/S3 执行器测试通过；不主动向真实接口触发 429。
- 尚未把目录/项目列表的非详情接口纳入同一限流通道，亦未将批量 ZIP 导出的每个完成分卷保存为恢复检查点。此阶段只可宣称 **详情 API** 已统一调度和冷却，不代表 S3 整体验收完成。

## 2026-10-24：S3-4 结构化运行日志与保留期

状态：运行日志底层完成；S3 仍有导出任务恢复与 Popup 展示未完成。

- 在原有 `logs` 区按账号保存结构化事件；429 冷却、任务暂停/继续/取消及单项处理失败触发记录。日志保存时间、任务 ID、事件类型、固定结果码和少量状态文字，不包含原始 JSON、消息正文、Cookie 或访问令牌。
- `logList` 支持按账号获取最近最多 500 条，写入新日志时自动删除超过 30 天的旧记录。日志写入失败不能导致已成功的任务控制或冷却释放操作失败。
- 隔离浏览器验证：429 和任务暂停均产生记录，账号隔离成立，旧日志在新增日志时清理，无令牌泄漏；既有 S1/S2/S3 测试不重复执行额外网络请求。
- 待 S5 在 Popup 展示日志及任务状态。清理规则是“写入时清理”，不是无人运行时后台定时清理。

## 2026-10-24：S3-5a 分卷 ZIP 的原子存储和断点检查点

状态：持久化分卷存储完成，页面的批量导出执行器尚待切换。

- IndexedDB 从 v2 升级到 v3，新增 `taskVolumes` 保存可重新下载的 ZIP Blob，原始对话、全文搜索、旧索引及任务、日志继续保留；v1 的旧索引可直接升级到 v3，不自动归属当前账号。
- 分卷保存 `taskVolumeSave` 以任务租约 token、下一个处理索引、分卷编号、完整 ZIP Blob 和 manifest 条目为输入，同一事务内提交 Blob 与任务 cursor、计数/错误条目。保存失败则 cursor 不会前进，避免出现跳过未保存数据的虚假进度。
- `taskVolumeGet` 可按账号、任务 ID、分卷编号取回 ZIP Blob；禁止跨账号读取、重复编号保存、旧执行者修改已暂停任务；已完成分卷的二进制内容不因刷新页面而消失。
- 隔离 Chrome 测试验证：升级保留旧数据、跨账号拒读写、首卷原子提交、同编号拒重复、暂停与换 token 后继续、完成任务的分卷/错误统计。
- 新增的 ZIP Blob 是可供将来重新下载的完整副本，**不会**把 Chrome 下载动作当作已经成功落盘。持久化后的清理交互将在任务管理阶段统一规划，当前不自动删除。

## 2026-10-24：S3-5b 兼容 Chrome JSON 消息的 ZIP 分块传输

- 为避免扩展运行时消息的 JSON 序列化将 `Blob` 变成空对象，IndexedDB 升级到 v4，增加临时 `taskVolumeChunks` 区；通过有长度上限的 Base64 分块逐条写入后，后台按序读取、验证租约、重建 ZIP `Blob` 并通过 S3-5a 的原子保存接口提交。
- 分块写入也要求任务所属账号、当前租约 token 和正确分卷序号。提交 ZIP 后自动清理对应临时分块，失败时保留阶段数据但不会推进任务检查点。
- 已保存分卷可以用 `taskVolumeGet` 读取元数据，再按偏移用 `taskVolumeRead` 返回 Base64 小块以供页面重新组装下载；不通过 JSON 消息直接返回巨大 Blob。
- 使用隔离 Chrome 的真实 IndexedDB 验证分块上传、最终组装后逐字节一致、账号隔离，以及原有 ZIP 与任务相关测试通过。S3-5c 将使实际批量导出循环使用该传输通路。
